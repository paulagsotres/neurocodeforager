summary:
MEDiCINe estimates brain motion (drift) during electrophysiology recordings by jointly optimizing two components — a motion function and an activity distribution along the probe — via gradient descent on detected spike amplitudes, depths, and times. It plugs directly into SpikeInterface and Kilosort4 pipelines, requires no manual parameter tuning, and produces motion estimates as simple numpy arrays.

abstract_long:
Probe drift during extracellular recordings distorts spike waveforms and degrades spike sorting quality. MEDiCINe addresses this by decomposing neural activity data into two jointly-optimized components: a motion function m(t, depth) describing how the brain moves relative to the probe over time and depth, and an activity distribution a(depth) describing the baseline firing rate distribution along the probe. These are fit simultaneously via gradient descent to maximize the likelihood of the observed spike amplitude-depth-time dataset. No labeled data is required — the model trains entirely on detected spikes from the session itself. The output is a motion array (time_bins × depth_bins) in microns that plugs directly into SpikeInterface's InterpolateMotionRecording or Kilosort4's datashift module. The authors validated on dozens of non-human primate datasets and report that hyperparameters almost never need tuning.

tutorial_intro:
MEDiCINe is installed as <code>medicine-neuro</code> from PyPI. The single entry point is <code>medicine.run_medicine()</code>, which takes spike amplitudes, depths, and times as numpy arrays and writes motion estimates to an output directory. It does not process raw voltage — any upstream spike detector works. The most common use is as a drop-in motion correction step inside a SpikeInterface pipeline, but it also integrates with Kilosort4 directly.

tutorial_steps:
Install and verify with the demo: <code>pip install medicine-neuro &amp;&amp; python -m medicine_demos.run_demo</code>. The demo downloads a sample dataset and shows motion estimation figures.
Run motion estimation — pass detected spike amplitudes, depths, and times (as numpy arrays, in microns and seconds) to <code>medicine.run_medicine(peak_amplitudes=..., peak_depths=..., peak_times=..., output_dir=Path('medicine_output'))</code>. These can come from SpikeInterface peak detection, Kilosort, or any other detector.
Load results from the output directory: <code>motion = np.load('medicine_output/motion.npy')</code> (shape: n_time_bins × n_depth_bins, units: microns), plus <code>time_bins.npy</code> and <code>depth_bins.npy</code> for the bin centers.
Apply motion correction in SpikeInterface by wrapping the output in a <code>Motion</code> object and passing it to <code>InterpolateMotionRecording(recording, motion_object)</code>, then feed the corrected recording to your spike sorter with its built-in motion correction disabled.
Check the output figures in <code>medicine_output/</code>, especially <code>corrected_motion_raster.png</code>. Defaults work for most datasets — only consider adjusting <code>motion_bound</code> (large drift), <code>time_kernel_width</code> (fast motion), or <code>amplitude_threshold_quantile</code> (noisy detections). See the README for Kilosort4 integration and the full parameter reference.

tutorial_output:
<code>motion.npy</code>: estimated probe motion in microns (n_time_bins × n_depth_bins). <code>time_bins.npy</code> and <code>depth_bins.npy</code>: corresponding bin centers. Diagnostic figures saved to <code>output_dir</code> including raw raster, motion overlay, and corrected raster.
