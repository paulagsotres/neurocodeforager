summary:
MEDiCINe estimates brain motion (drift) during electrophysiology recordings by jointly optimizing two components — a motion function and an activity distribution along the probe — via gradient descent on detected spike amplitudes, depths, and times. It plugs directly into SpikeInterface and Kilosort4 pipelines, requires no manual parameter tuning, and produces motion estimates as simple numpy arrays.

abstract_long:
Probe drift during extracellular recordings distorts spike waveforms and degrades spike sorting quality. MEDiCINe addresses this by decomposing neural activity data into two jointly-optimized components: a motion function m(t, depth) describing how the brain moves relative to the probe over time and depth, and an activity distribution a(depth) describing the baseline firing rate distribution along the probe. These are fit simultaneously via gradient descent to maximize the likelihood of the observed spike amplitude-depth-time dataset. No labeled data is required — the model trains entirely on detected spikes from the session itself. The output is a motion array (time_bins × depth_bins) in microns that plugs directly into SpikeInterface's InterpolateMotionRecording or Kilosort4's datashift module. The authors validated on dozens of non-human primate datasets and report that hyperparameters almost never need tuning.

tutorial_intro:
MEDiCINe is installed as <code>medicine-neuro</code> from PyPI. It takes spike amplitudes, depths, and times (not raw voltage) as input — the output of any upstream spike detector — and writes motion estimates to an output directory. The most common use is as a drop-in motion correction step inside a SpikeInterface pipeline.

tutorial_steps:
Install via pip (<code>pip install medicine-neuro</code>) and run the bundled demo (<code>python -m medicine_demos.run_demo</code>) to verify the installation and see example output figures.
Detect spikes from your recording using SpikeInterface, Kilosort, or any other detector. MEDiCINe needs only the spike amplitudes, depths (in microns), and times (in seconds) — not the raw traces.
Run <code>medicine.run_medicine()</code> passing the spike arrays and an output directory. The model trains on the session's own data without any labeled examples and writes the motion estimates as numpy arrays.
Apply the resulting motion correction in your SpikeInterface pipeline by wrapping the output in a <code>Motion</code> object and using <code>InterpolateMotionRecording</code>. If using Kilosort4 directly, see the README for the datashift integration snippet.
Check the diagnostic figures saved to the output directory (especially <code>corrected_motion_raster.png</code>). Defaults work for most datasets; the README documents the few parameters worth adjusting if results look off.

tutorial_output:
<code>motion.npy</code>: estimated probe motion in microns (n_time_bins × n_depth_bins). <code>time_bins.npy</code> and <code>depth_bins.npy</code>: corresponding bin centers. Diagnostic figures saved to the output directory including raw raster, motion overlay, and corrected raster.
