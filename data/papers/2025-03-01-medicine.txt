summary:
MEDiCINe estimates brain motion (drift) during electrophysiology recordings by jointly optimizing two components — a motion function and an activity distribution along the probe — via gradient descent on detected spike amplitudes, depths, and times. It plugs directly into SpikeInterface and Kilosort4 pipelines, requires no manual parameter tuning across dozens of NHP datasets, and produces motion estimates as simple numpy arrays.

abstract_long:
Probe drift during extracellular recordings distorts spike waveforms and degrades spike sorting quality. MEDiCINe addresses this by decomposing neural activity data into two jointly-optimized components: a motion function m(t, depth) describing how the brain moves relative to the probe over time and depth, and an activity distribution a(depth) describing the baseline firing rate distribution along the probe. These are fit simultaneously via gradient descent to maximize the likelihood of the observed spike amplitude-depth-time dataset. No labeled data is required — the model trains entirely on detected spikes from the session itself. The output is a motion array (time_bins × depth_bins) in microns that plugs directly into SpikeInterface's InterpolateMotionRecording or Kilosort4's datashift module. The authors validated on dozens of NHP datasets and report that hyperparameters almost never need tuning.

tutorial_intro:
MEDiCINe is installed as <code>medicine-neuro</code> from PyPI. The single entry point is <code>medicine.run_medicine()</code>, which takes spike amplitudes, depths, and times as numpy arrays and writes motion estimates to an output directory. It does not process raw voltage — any upstream spike detector works. The most common use is as a drop-in motion correction step inside a SpikeInterface pipeline, but it also integrates with Kilosort4 directly.

tutorial_steps:
Install and verify:
<code>pip install medicine-neuro
python -m medicine_demos.run_demo</code>
The demo downloads a sample dataset and displays motion estimation figures.

Run motion estimation by passing detected spike times, depths, and amplitudes to <code>medicine.run_medicine()</code>. These can come from SpikeInterface peak detection, Kilosort, or any other detector:
<code>import medicine
from pathlib import Path

output_dir = Path('medicine_output')
output_dir.mkdir(parents=True, exist_ok=True)

medicine.run_medicine(
    peak_amplitudes=...,   # 1D array, shape (n_spikes,)
    peak_depths=...,       # 1D array, depth in microns
    peak_times=...,        # 1D array, time in seconds
    output_dir=output_dir,
)

# Results
motion     = np.load(output_dir / 'motion.npy')      # (n_time_bins, n_depth_bins)
time_bins  = np.load(output_dir / 'time_bins.npy')
depth_bins = np.load(output_dir / 'depth_bins.npy')</code>

Apply motion correction in a SpikeInterface pipeline using the output arrays:
<code>from spikeinterface.core.motion import Motion
from spikeinterface.sortingcomponents.motion.motion_interpolation import InterpolateMotionRecording

motion_object = Motion(
    displacement=motion,
    temporal_bins_s=time_bins,
    spatial_bins_um=depth_bins,
)
recording_corrected = InterpolateMotionRecording(
    recording, motion_object, border_mode='force_extrapolate'
)
# Pass recording_corrected to your spike sorter with its built-in motion correction disabled</code>

Check the figures saved to <code>output_dir/</code>, especially <code>corrected_motion_raster.png</code>. The defaults work for most datasets — the only parameters worth adjusting are <code>motion_bound</code> (increase if drift is very large), <code>time_kernel_width</code> (decrease if motion is fast), and <code>amplitude_threshold_quantile</code> (increase to exclude noisy low-amplitude spikes). See the README for the full parameter reference and Kilosort4 integration instructions.

tutorial_output:
<code>motion.npy</code>: estimated probe motion in microns (n_time_bins × n_depth_bins). <code>time_bins.npy</code> and <code>depth_bins.npy</code>: corresponding bin centers. Diagnostic figures saved to <code>output_dir</code> including raw raster, motion overlay, and corrected raster.
