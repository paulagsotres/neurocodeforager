summary:
CellRake is a lightweight Python package (<30 KB) for automated detection and counting of fluorescently labeled cells in brain sections. It uses a two-step pipeline: Laplacian-of-Gaussian blob segmentation followed by semi-supervised random forest classification trained on a handful of manually labeled blobs per image — no GPU, no large annotated dataset, no ImageJ or ROI drawing required. Validated against manual counts: cFos r=0.944, tdTomato r=0.879, colocalization r=0.912.

abstract_long:
Manual counting of fluorescently labeled cells (cFos, tdTomato, or any marker) across many brain regions and animals is slow, biased, and irreproducible. Existing automated tools (QuPath, CellProfiler, Ilastik, Cellpose) are powerful but require extensive customization, large labeled datasets, or GPU resources. CellRake is designed for the single task of detecting and counting fluorescent marker-positive cells in brain section images, with a learning curve that lets users train a working classifier in minutes from their own images.

The pipeline has two stages. First, segmentation: a Laplacian of Gaussian (LoG) filter detects candidate blob-like structures regardless of background intensity heterogeneity, followed by per-blob adaptive Otsu thresholding, morphological cleanup (remove small objects and holes, area constraints), and a marker-based watershed step to separate overlapping signals — consistently outperforming global thresholding methods (Otsu, Multi-Otsu, Li, Yen) on images with variable backgrounds. Second, classification: CellRake extracts 22 morphological and intensity features per blob (area, perimeter, eccentricity, mean intensity, intensity ratio, intensity difference, SD intensity, HOG features, etc.), clusters them with k-means (10 clusters by default), presents ~25 representative blobs per cluster for the user to label as positive (1) or negative (0) in an interactive matplotlib window, applies SMOTE to balance classes, uses KNN label spreading retaining only high-confidence predictions (entropy < 0.025), then trains a final supervised classifier (random forest, SVM, extra trees, or logistic regression). The model is evaluated on held-out data and returns ROC AUC, average precision, precision, recall, and F1. Validated on 153 BLA images from 36 mice: cFos r=0.944, tdTomato r=0.879, colocalization r=0.912 vs manual counts, and shown to generalise to DG and PAGd with very different cellular density and background.

tutorial_intro:
CellRake is controlled entirely through a single <code>CellRake</code> class in <code>cellrake.main</code>. The recommended installation is via conda + pip (Python 3.9–3.10 strictly). The workflow has two independent phases: <strong>training</strong> (interactive — you label ~25 blobs per cluster from a representative image set, the model learns) and <strong>analysis</strong> (batch — run the trained model on all images automatically). Train one model per marker type (e.g. one for cFos, one for tdTomato). You can save and reload both the trained model and the segmentation data to avoid repeating expensive steps. For colocalization across two markers, run each independently and then combine the outputs.

tutorial_steps:
Create a conda environment with Python 3.10 and install CellRake from PyPI:
<code>conda create --name cellrake python=3.10
conda activate cellrake
pip install cellrake
# To update later:
pip install cellrake --upgrade</code>
Organise your TIFF images into one folder per marker type (e.g. <code>images/cfos/</code>, <code>images/tdtomato/</code>). Create a separate <code>project_dir</code> folder per marker — this is where the model file, segmentation cache, result CSVs, and overlay QC images will be saved.

Import and initialise a <code>CellRake</code> object pointing at your image folder and project directory:
<code>from pathlib import Path
from cellrake import CellRake

cr = CellRake(
    project_dir=Path("results/cfos"),     # will be created if it doesn't exist
    image_folder=Path("images/cfos")      # folder of TIFF images to process
)</code>
The <code>project_dir</code> is created automatically. <code>image_folder</code> must exist and contain TIFF files.

Run the training phase. CellRake will: (1) segment all images with a LoG filter, (2) extract 22 features per blob, (3) cluster blobs with k-means, (4) display ~25 blobs per cluster in a matplotlib window and prompt you to type <code>1</code> (cell) or <code>0</code> (non-cell) in the terminal, (5) apply SMOTE + label spreading + supervised training:
<code>cr.train(
    threshold_rel=0.1,   # blob detection sensitivity (0–1); start here and adjust
    model_type="rf",     # classifier: "rf" (random forest), "svm", "et", "logreg"
    samples=25           # blobs shown per k-means cluster for manual labeling
)</code>
The interactive labeling window shows 4 panels: full image with ROI highlighted, full image without, cropped with ROI, cropped without. Type <code>1</code> or <code>0</code> and press Enter for each blob. This takes 5–15 minutes depending on the number of clusters. After labeling, CellRake prints ROC AUC, precision, recall, and F1 on the held-out test set.
Key segmentation parameters you can tune if the default segmentation misses cells or produces too many false blobs:
<code>cr.train(
    threshold_rel=0.05,       # lower = more blobs detected
    max_sigma=10,             # larger = finds bigger blobs (LoG filter)
    min_area=50,              # minimum blob area in pixels
    max_area=5000,            # maximum blob area in pixels
    radius_expansion=1.5,     # how much to expand the detected blob radius
    entropy_threshold=0.025   # confidence cutoff for label spreading (lower = stricter)
)</code>

Save the trained model to disk so you never have to re-label:
<code>cr.save_model("cfos_model")     # saved as results/cfos/cfos_model.pkl

# In a future session:
cr2 = CellRake(project_dir=Path("results/cfos"))
cr2.load_model("cfos_model")</code>
You can also save and reload the segmentation cache (useful for large image sets to avoid re-running the LoG filter step, which is the slowest part):
<code>cr.save_segmentation("cfos_seg")
# Later:
cr.load_segmentation("cfos_seg")</code>

Apply the trained model to all images and export results:
<code>counts, features = cr.analyze(
    threshold_rel=0.1,   # use the same value as during training
    cmap="Greens"        # colormap for the overlay QC images (e.g. "Reds" for tdTomato)
)</code>
<code>counts</code> is a pandas DataFrame with per-image positive cell counts — automatically saved to <code>results/cfos/cell_counts.csv</code>. <code>features</code> is a per-blob feature table saved to <code>cell_features.csv</code>. CellRake also saves overlay images with detected cells highlighted in the chosen colormap for visual QC.

To analyse a second batch of images (e.g. new animals or a different brain region) with the same trained model, update the folders before calling <code>.analyze()</code>:
<code>cr.set_image_folder(Path("images/cfos_batch2"))  # clears segmentation cache automatically
cr.set_project_dir(Path("results/cfos_batch2"))
counts2, _ = cr.analyze(threshold_rel=0.1)</code>

For colocalization between two markers in the same section (e.g. tdTomato and cFos), run the full training + analysis pipeline independently for each marker with separate <code>CellRake</code> objects. CellRake identifies colocalized detections from the two output files: two blobs are considered colocalized if their overlap area (computed via Shapely polygon intersection) is at least 80% of the smaller blob's area. The colocalization count per image is reported alongside single-marker counts. In the paper this approach achieved r=0.912 vs manual colocalization counts.

tutorial_output:
<code>cell_counts.csv</code>: one row per image, positive cell count per marker — ready for statistical modelling. The paper fits GLMMs with Negative Binomial distribution (due to overdispersion) and zero-inflation for tdTomato, using log-transformed ROI area as an offset and animal ID as a random effect (implemented in R with glmmTMB, or Python with statsmodels). <code>cell_features.csv</code>: per-blob feature table (22 features including area, perimeter, eccentricity, mean/SD/ratio intensity, HOG features) for QC or further analysis. Overlay images in <code>project_dir</code> for visual inspection of detected cells.
